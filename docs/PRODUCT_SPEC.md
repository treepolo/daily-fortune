# 今日運勢：產品規格

## 1. 產品核心

「今日運勢」是一個每日由使用者親自抽取運勢、並可反覆「逆天改命!!」重新抽籤的 Android App。

目前產品不使用星座、天文、占星、公共統一命運或卜辭。每個人的每日結果由自己的抽籤行為產生。

第一版核心吸引力不是單純顯示一組隨機結果，而是「親手求籤 → 等待命數落定 → 親手揭籤 → 看到有強烈情緒差異的結果」這整段儀式。

核心流程：

1. 今日尚未抽籤時，畫面顯示籤筒與可抓取的籤。
2. 使用者按住籤往上抽；只有跨過抽離門檻後才正式建立本次 draw。
3. 籤抽出後進入具有 suspense 的結果落定階段，結果不能立刻顯示。
4. 結果落定後顯示仍被遮蔽／折疊的籤紙。
5. 使用者按住籤紙下緣往下拉，同一張固定版面籤紙逐步展開，結果由上到下自然露出。
6. 已有結果後可按「逆天改命!!」。這個按鈕本身不直接抽新結果，而是回到籤筒待抽狀態；使用者再次親手抽出籤後才建立 reroll。

第一版視覺核心採台灣廟宇／求籤風格。抽籤與揭籤是產品核心，不是裝飾動畫。

## 2. 運勢項目與數值

每次抽籤同時產生五個細項：

- 財運
- 戀愛
- 工作／學業
- 人際
- 健康

七級運勢：

| 數值 | 等級 |
|---:|---|
| 1 | 大凶 |
| 2 | 凶 |
| 3 | 小凶 |
| 4 | 平 |
| 5 | 小吉 |
| 6 | 吉 |
| 7 | 大吉 |

目前正式 baseline：

- 五個細項彼此獨立抽取。
- 每個細項的 1～7 機率相同，皆為 1/7。
- 初次抽籤與 reroll 使用相同均勻分布。
- 抽樣為放回抽樣；允許重抽後得到與前一籤完全相同的結果。
- 次數加成關閉。
- pity／保底關閉。

以上皆屬可實驗參數，不得硬寫死成未來無法遠端變更的產品假設。

## 3. 總體吉凶

每次抽籤先取得五個細項整數分數，再計算算術平均：

`rawAverage = (財運 + 戀愛 + 工作／學業 + 人際 + 健康) / 5`

目前 baseline 以「無條件捨去」將平均值轉為 1～7 的總體等級。

總體判定規則須支援 Remote Config，至少包含：

- 全區間 floor
- 全區間 ceil
- 全區間 round
- piecewise：不同平均值區間可分別指定 floor / ceil / round

分段規則使用明確區間邊界，例如 `[1,2)`、`[2,6)`、`[6,7]`。

## 4. 每日狀態與 draw 提交時機

「一天」依裝置當下系統時區與當地日期判斷，不固定使用台北時間。

行為規則：

- 開啟 App 不會自動抽籤。
- 今天尚未抽籤時，只顯示待抽籤筒，不建立 draw。
- 使用者只是碰到／拖動籤但沒有跨過抽離門檻時，不建立 draw。
- 使用者把籤拉過提交門檻後才建立初次 draw 或 reroll。
- 如果今天只開啟 App、沒有真正抽出籤，不建立當日 fortune draw。
- 當日已抽過後重新開啟 App，直接顯示當日最後一次完整結果，不強迫重播抽籤與揭籤流程。
- 跨日後不沿用前一天結果；新的一天重新等待使用者親自抽籤。
- 「逆天改命!!」沒有每日次數上限。
- 按「逆天改命!!」只回到待抽狀態；未再次抽出籤前，不建立新的 reroll。

## 5. 第一版核心 UI／互動

### 5.1 視覺方向

- 台灣廟宇／求籤語彙。
- 主色以廟宇紅、金、深色木質／墨色、竹籤與籤紙色為基礎。
- 主要物件包含籤筒、籤、籤紙。
- 字體氣質偏傳統／明體感；不加入卜辭。
- 第一版可使用程式化廟宇框架、紋理與光效，不依賴外部照片。
- 日後若加入廟宇照片，優先使用使用者自行拍攝或授權條件明確、可商用／修改的素材。

### 5.2 抽籤互動

待抽狀態必須讓使用者直接操作籤：

1. 可抓取的籤明顯從籤筒中伸出。
2. 使用者按住籤向上拖。
3. 未達抽離門檻時，放手可回到原位，不建立結果。
4. 達抽離門檻時給予觸覺回饋並正式提交 draw。
5. 進入結果落定／suspense 階段。

### 5.3 Suspense

抽出籤後不立即顯示答案。Reveal 前必須有明顯張力與等待感，讓使用者清楚感覺到「結果已經開始決定，但還不能看」。

基準效果可使用廟宇紅金、放射線、脈衝、籤／印記等程式化視覺，不要求真 3D 或重型粒子。

### 5.4 籤紙揭曉

結果不是一次全部出現，也不是程式依時間一列一列跳出。

籤紙本身是一個固定版面；開始時只露出上方一小段，其餘內容被遮蔽。使用者按住籤紙下緣往下拖，紙張可見高度跟著手指增加，因此固定內容自然依序露出：

1. 財運
2. 戀愛
3. 工作／學業
4. 人際
5. 健康
6. 總體運勢

總體運勢位於最下方，作為揭籤壓軸。

重要節點加入震動回饋，至少包含：

- 籤真正抽離／draw 提交
- 籤紙已可開始揭曉
- 籤紙完整揭開／總體結果完成曝光

### 5.5 各細項與總體的吉凶特效

每個細項依自己的 1～7 級顯示自己的情緒與光效，不只讓總體背景變色。

整體原則：

- 大凶：特別極端；近乎無光、低彩、晦暗、壓抑，與「凶」明顯拉開。
- 凶：暗、冷、低彩。
- 小凶：仍偏暗，但比凶稍有暖色與可讀性。
- 平：中性廟宇紅金基調。
- 小吉：開始增加暖色與微光。
- 吉：明顯金光、亮度與擴張感。
- 大吉：特別極端；高亮金色、閃耀、放射光，可加入多彩光暈，與「吉」明顯拉開。

大吉與大凶不是單純七級連續梯度的兩端，而是額外強調的 extreme states。

目前不顯示：

- 個人歷史統計
- 改命總次數、每日平均、最高次數
- 歷史抽籤紀錄
- 星座
- 十二星座跑馬燈
- 天文／占星資訊
- 平行宇宙／平行天空資訊
- 卜辭、題詞或解釋文字

## 6. 本機歷史資料

前端雖不顯示個人統計，但每次真正提交的抽籤仍需保留本機事件紀錄，以支援：

- 當日最後結果復原
- 離線操作
- 研究事件可靠上傳
- 後續除錯與一致性檢查

每一次初抽與每一次真正完成的 reroll 都是獨立、不可覆寫的 draw event；每日狀態只保存目前應顯示哪一筆 draw。

## 7. 研究與 A/B/n 實驗

產品從第一版架構支援匿名行為研究與 A/B/n 多臂實驗。實驗不限兩組，可同時存在 A、B、C、D……任意多個 variant，且各 variant 可有不同流量權重。

### 7.1 可遠端實驗的抽籤參數

至少支援：

- 初次抽籤的 1～7 機率分布
- baseline reroll 的 1～7 機率分布
- 五細項是否獨立
- 五細項之間的相關結構／相關矩陣
- 總體平均值轉等級規則
- 靜態視覺 variant ID
- 動態／揭曉互動 variant ID
- 依 reroll 次數切換不同完整 1～7 分布的 schedule
- pity／保底機制

### 7.2 動態機率與保底

App 需預先具備以下能力，但 baseline 預設關閉：

#### Reroll schedule

Remote Config 可依 `reroll_index` 指定不同完整七級機率分布。例如第 1～3 次、4～7 次、8 次以後使用不同分布。

不是只提供單一「每抽 +X%」參數，而是每個區間可提供完整 1～7 probability vector，以支援線性、階梯、非線性或其他實驗設計。

#### Pity／保底

Remote Config 可設定：

- 是否啟用
- 連續未達成成功條件幾次後觸發
- 成功門檻分數
- 保底 scope

目前預先支援的 scope：

- `OVERALL_AT_LEAST`：總體至少達指定等級
- `ANY_DOMAIN_AT_LEAST`：至少一個細項達指定等級

baseline：pity OFF。

### 7.3 不要求使用者更新 App

已被 App 支援的實驗能力，可透過後端 Remote Config 改變，不要求使用者重新下載 APK。

例如：

- 機率分布
- variant 權重
- 相關矩陣
- floor / ceil / round / piecewise
- reroll schedule
- 既有 pity 參數
- 已存在於 App 的視覺／互動 variant

如果要測 App 尚未實作的新演算法、新 pity scope、新視覺元件或新互動能力，仍需要發布新版本。

### 7.4 穩定分組

同一匿名 installation 在同一 experiment/version 期間必須穩定落在同一 variant，不得因每次開啟 App 而重新抽組。

後端可同時存在多個實驗；App 接收後端解析完成的有效設定，以及本次設定涉及的 experiment/variant assignments。

### 7.5 Exposure

資料系統須區分「被分配到某 variant」與「實際看到／使用該 treatment」。因此實際發生 treatment 時需記錄 experiment exposure，或在對應行為事件中攜帶實際 assignments。

## 8. 研究資料

使用者端 App 不提供研究 Dashboard，也不顯示群體統計。研究／統計分析系統與 Android App 分離。

App 只負責：

1. 取得遠端實驗設定。
2. 執行該設定。
3. 上傳匿名行為事件。

研究端另外使用資料庫、SQL、Python、Notebook 或 Dashboard 分析。

### 8.1 匿名識別

第一版使用隨機產生的匿名 `installation_id`，不要求登入帳號，也不為研究目的收集姓名、Email、聯絡人或精確位置。

每次 session 使用新的 `session_id`。

### 8.2 基礎事件

至少記錄：

- `app_open`
- `session_start`
- `session_end`
- `experiment_exposure`
- `initial_draw`
- `reroll`

視覺／互動研究可增加：

- `animation_started`
- `animation_completed`
- `result_revealed`
- 未來若需要，可再加入 stick pull / paper reveal 類事件，但不要求 baseline 立即全部上報。

### 8.3 事件共同欄位

至少包含：

- event ID
- installation ID
- session ID
- UTC timestamp
- 裝置當地時間
- timezone ID
- App version
- experiment ID / variant ID / config ID
- event-specific payload

抽籤事件還需包含：

- fortune date
- draw index
- reroll index
- 初抽或 reroll
- 五細項原始分數
- raw average
- 最終 overall grade
- effective distribution ID
- sampling/correlation profile ID
- overall rule ID
- probability policy ID
- pity counter
- guarantee triggered

上述欄位用來區分「使用者本身抽到較好結果」與「系統因 schedule／保底調整而改變結果機率」。

## 9. 主要研究指標

研究系統應可計算至少：

- session duration
- sessions per user/day
- draws per session
- rerolls per initial draw
- 首次抽籤轉換率
- 抽完後立即離開比例
- 結果揭曉到 reroll 的延遲
- D1 / D7 等回訪／留存指標

不能只用「使用時間更長」或「抽籤次數更多」單一指標判定 treatment 較佳，因為摩擦、動畫時長或負面體驗也可能機械式提高這些數字。

比較 reveal／互動 treatment 時尤其要避免把「動畫本身比較長」誤認為 engagement 提升。

## 10. 未來但本輪不實作

- v0.6 baseline 以外的大量動畫／視覺 variant
- 完整 3D 廟宇場景
- 真實籤筒物理模擬
- 重型粒子系統
- 廣告：一般情況按「逆天改命!!」後，在再次抽籤流程前可要求完整廣告；若當前總體結果為大吉則可免廣告
- 帳號、跨裝置同步
- 社交／公開「綁凶籤」功能
- 卜辭／題詞內容
- 使用者端歷史統計

上述項目不得反向綁死核心抽籤引擎。
