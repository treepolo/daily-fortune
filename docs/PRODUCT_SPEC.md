# 今日運勢：產品規格

## 1. 產品核心

「今日運勢」是一個每日由使用者親自抽取運勢、並可反覆按「逆天改命!!」重抽的 Android App。

目前產品不使用星座、天文、占星、公共統一命運或卜辭。每個人的每日結果由自己的抽籤行為產生。

核心體驗只有兩個動作：

1. 今天尚未抽籤時，使用者親自按下「抽籤」。
2. 已有結果後，使用者可不限次數按「逆天改命!!」重新抽取。

## 2. 運勢項目與數值

每次抽籤同時產生五個細項：

- 財運
- 戀愛
- 工作／學業
- 人際
- 健康

七級運勢以數值 1～7 表示：

| 數值 | 等級 |
|---:|---|
| 1 | 大凶 |
| 2 | 凶 |
| 3 | 小凶 |
| 4 | 平 |
| 5 | 小吉 |
| 6 | 吉 |
| 7 | 大吉 |

目前正式預設：

- 五個細項彼此獨立抽取。
- 每個細項的 1～7 機率相同，皆為 1/7。
- 初次抽籤與「逆天改命!!」使用相同分布。
- 抽樣為放回抽樣；允許重抽後得到與前一籤完全相同的結果。

以上皆屬可實驗參數，不能硬寫死成未來無法遠端變更的產品假設。

## 3. 總體吉凶

每次抽籤先取得五個細項的整數分數，再計算算術平均：

`rawAverage = (財運 + 戀愛 + 工作／學業 + 人際 + 健康) / 5`

目前預設以「無條件捨去」將平均值轉為 1～7 的總體等級。

總體判定規則必須支援遠端設定，至少包含：

- 全區間無條件捨去（floor）
- 全區間無條件進位（ceil）
- 全區間四捨五入（round）
- 分段規則（piecewise），每個平均值區間可分別指定 floor / ceil / round

分段規則使用明確區間邊界，例如 `[1,2)`、`[2,6)`、`[6,7]`，避免 2、6 等邊界值產生歧義。

## 4. 每日狀態

「一天」依裝置當下的系統時區與當地日期判斷，不固定使用台北時間。

行為規則：

- 開啟 App 不會自動抽籤。
- 今天尚未抽籤時，只顯示可執行的初次抽籤操作。
- 使用者只有在親自按下「抽籤」後才建立當日結果。
- 如果今天只開啟 App、沒有抽籤，不建立當日 fortune draw。
- 當日已抽過後重新開啟 App，直接顯示當日最後一次抽取的結果。
- 跨日後不沿用前一天的結果；新的一天重新等待使用者親自抽籤。
- 「逆天改命!!」每按一次都重抽五個細項並取代前端目前顯示的結果。
- 「逆天改命!!」沒有每日次數上限。

## 5. 前端顯示

目前前端只需呈現：

- 今日是否已抽籤
- 總體吉凶
- 五個細項吉凶
- 初次「抽籤」按鈕
- 已抽籤後的「逆天改命!!」按鈕
- 必要的 loading / error 狀態

目前不顯示：

- 個人歷史統計
- 改命總次數、每日平均、最高次數
- 歷史抽籤紀錄
- 星座
- 十二星座跑馬燈
- 天文／占星資訊
- 平行宇宙／平行天空資訊
- 卜辭、題詞或解釋文字

動態與靜態視覺效果是未來必要的實驗項目，但本輪不實作具體動畫；架構只保留可遠端指定視覺 variant 的能力。

## 6. 本機歷史資料

前端雖不顯示個人統計，但每次實際抽籤仍需保留本機事件紀錄，以支援：

- 當日最後結果復原
- 離線操作
- 研究事件可靠上傳
- 後續除錯與一致性檢查

每一次初抽與每一次逆天改命都是獨立、不可覆寫的 draw event；每日狀態只保存「目前應顯示哪一筆 draw」。

## 7. 研究與 A/B/n 實驗

產品必須從第一版架構上支援匿名行為研究與 A/B/n 多臂實驗。實驗不限兩組，可同時存在 A、B、C、D……任意多個 variant，且各 variant 可有不同流量權重。

### 7.1 可遠端實驗的抽籤參數

至少支援：

- 初次抽籤的 1～7 機率分布
- 逆天改命的 1～7 機率分布
- 五細項是否獨立
- 五細項之間的相關結構／相關矩陣
- 總體平均值轉等級規則
- 未來的靜態視覺 variant ID
- 未來的動態／揭曉動畫 variant ID

目前預設為五細項獨立、1～7 均勻分布、初抽與重抽相同、總體 floor。

### 7.2 不要求使用者更新 App

已經被 App 支援的實驗能力，必須透過後端 Remote Config 改變參數，不要求使用者重新下載或更新 APK。

界線如下：

- 實驗內容與參數由後端遠端配置。
- App 版本提供可執行的能力集合。
- 如果只是改機率、variant 權重、相關矩陣、floor/ceil/round/piecewise 規則或既有視覺 variant，無須更新 App。
- 如果要測 App 尚未實作過的新演算法或新視覺元件，才需要發布新版本。

### 7.3 穩定分組

同一匿名 installation 在同一個 experiment/version 期間必須穩定落在同一 variant，不得因每次開啟 App 而重新抽組。

後端可同時存在多個實驗；App 接收的是後端解析完成的有效設定，以及本次設定涉及的 experiment/variant assignments。

### 7.4 Exposure

資料系統必須能區分「被分配到某 variant」與「實際看到／使用該 treatment」。因此實際發生 treatment 時需記錄 experiment exposure，或在對應行為事件中攜帶實際使用的 assignments。

## 8. 研究資料

使用者端 App 不提供研究 Dashboard，也不顯示群體統計。研究／統計分析系統與 Android App 分離。

App 只負責：

1. 取得遠端實驗設定。
2. 執行該設定。
3. 上傳匿名行為事件。

研究端另外使用資料庫、SQL、Python、Notebook 或 Dashboard 分析。

### 8.1 匿名識別

第一版使用隨機產生的匿名 `installation_id`，不要求登入帳號，也不為研究目的收集姓名、Email、聯絡人或精確位置。

每次 session 使用新的 `session_id`。

### 8.2 基礎事件

至少記錄：

- `app_open`
- `session_start`
- `session_end`
- `experiment_exposure`
- `initial_draw`
- `reroll`

未來視覺實驗可增加：

- `animation_started`
- `animation_completed`
- `result_revealed`

### 8.3 事件共同欄位

至少包含：

- event ID
- installation ID
- session ID
- UTC timestamp
- 裝置當地時間
- 當下 timezone ID
- App version
- experiment ID / variant ID / config ID
- event-specific payload

抽籤事件還需包含：

- fortune date
- draw index
- 初抽或 reroll
- 五細項原始分數
- raw average
- 最終 overall grade
- distribution ID
- sampling/correlation profile ID
- overall rule ID

## 9. 主要研究指標

研究系統應可由事件資料計算至少：

- session duration
- sessions per user/day
- draws per session
- rerolls per initial draw
- 首次抽籤轉換率
- 抽完後立即離開比例
- 結果揭曉到 reroll 的延遲
- D1 / D7 等回訪／留存指標

不能只用「使用時間更長」或「抽籤次數更多」單一指標判定 treatment 較佳，因為摩擦或負面體驗也可能機械式提高這些數字。

## 10. 未來但本輪不實作

- 動態／靜態視覺效果實驗的具體素材與動畫
- 廣告：一般情況按「逆天改命!!」前觀看完整廣告；若當前結果為大吉則免廣告並可立即重抽
- 帳號、跨裝置同步
- 社交／公開「綁凶籤」功能
- 卜辭／題詞內容
- 使用者端歷史統計

上述項目不得重新反向綁死核心抽籤引擎。
