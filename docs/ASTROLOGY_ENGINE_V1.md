# Astrology Engine v1

Version: `astrology-v1.0.0`

本文件是「今日運勢」公共天命與私人平行天象共同使用的正式 v1 規則。**同一份天文輸入 + 同一個太陽星座 + 同一引擎版本必須得到同一結果。**引擎計分本身不得加入亂數。

公共世界線的輸入是今天真實天空；私人「逆天改命」先以安全亂數選擇另一個物理可成立的完整星曆天空，再把該天空送進完全相同的 Astrology Engine。

> 定位：這是一套依西方太陽星座占星傳統建立的娛樂性規則引擎。天體位置是天文計算；從天象推導吉凶屬占星術規則，不宣稱具有科學預測效力。

## 1. 不可違反的資料鏈

每個結果都必須能追溯：

`完整星曆 → 天文特徵 → 明確規則 → 領域加減分 → 總分 → 吉凶 → 詳情文字`

禁止：

- 日期＋星座種子、使用者 ID 種子或偽裝成天象的亂數。
- 獨立亂數修改各顆行星的位置。
- 算出吉凶後另抽不相關文案。
- 假設使用者出生時間、出生地或本命太陽精確度數。
- 後端失效時用固定種子或本機臨時結果冒充正式公共天命。

## 2. 天文引擎與座標

- 函式庫：Astronomy Engine `2.1.19`，MIT License。
- 正式天文計算不需要外部 API key。
- 驗證基準可使用 NASA/JPL Horizons。
- 使用地心視角、光行時與光行差校正後的 J2000 赤道向量，再轉為當日真黃道黃經。
- 黃道採熱帶黃道：春分點為牡羊座 0°，每 30° 一星座。
- 十二星座順序固定：牡羊、金牛、雙子、巨蟹、獅子、處女、天秤、天蠍、射手、摩羯、水瓶、雙魚。

天體：太陽、月亮、水星、金星、火星、木星、土星、天王星、海王星、冥王星。

## 3. 一天的取樣

一天定義為 `Asia/Taipei` 00:00:00 至下一日 00:00:00。

- 每 15 分鐘取樣一次。
- 包含首尾，共 97 個樣本。
- 96 個日內區間計算某天體在某星座占今日多久。
- 第 97 個樣本作為跨日端點，用於運動方向、換座與相位邊界判定。

這避免只拿中午單點而漏掉凌晨或晚間的重要天象。

## 4. 私人平行天象的選擇

這一節只決定「哪一份天文輸入」進引擎，不改變後續任何占星規則。

v1 正式流程：

1. 使用具安全性的伺服器亂數，等機率選 1900–2100 的年份，排除原年份。
2. 以原日期同月同日為中心，在目標年份的 ±6 日尋找候選日。
3. 對每個候選日計算 `Asia/Taipei` 正午太陽真黃道黃經。
4. 選擇與原日期正午太陽黃經角距最小者。
5. 採用該來源日完整 00:00–24:00 星曆，包含所有十個天體的位置與運動。
6. 送入下述相同 Astrology Engine。

這能近似保持季節／太陽背景，同時讓月亮與其他行星呈現另一組物理一致的星曆狀態。來源可能是歷史天空，也可能是星曆可預測的未來天空。

亂數不得直接決定吉凶，也不得在看到結果變差後偷偷重抽。相同來源日允許再次出現。

Android 開發原型使用 Java `SecureRandom`；正式 Supabase Edge Function 使用 Web Crypto `crypto.getRandomValues` 並採 rejection sampling 避免取模偏差。

## 5. 太陽星座與宮位

App 只有使用者太陽星座，因此 v1 採太陽星座整宮制：使用者太陽星座為第 1 宮，下一星座為第 2 宮，依序至第 12 宮。不假裝知道上升星座或精確本命太陽度數。

例如天蠍座使用者：天蠍第 1 宮、射手第 2 宮……天秤第 12 宮。

## 8. 行星落宮分數

對天體在今日占據的每個星座分別計算：

`基礎吉凶 × 行星領域關聯 × 宮位領域權重 × 尊貴倍率 × 時間占比 × 8`

一天內換座的天體按實際停留時間分攤。

## 9. 太陽星座級相位

因不知道出生太陽精確度數，只判定行運天體所在星座和使用者太陽星座的星座級關係：

| 星座距離 | 關係 | 基礎傾向 |
|---|---|---:|
| 0 | 合相 | 依行星本身性質 |
| 2 / 10 | 六合 | +.35 |
| 3 / 9 | 刑相 | -.45 |
| 4 / 8 | 拱相 | +.50 |
| 6 | 對分 | -.55 |

分數：

`關係傾向 × 行星領域關聯 × 尊貴倍率 × 時間占比 × 5`

文字必須標示這是星座級關係，不得寫成精確刑／合使用者本命太陽。

## 10. 天體彼此的主要相位

只採五個主要相位：

| 相位 | 角度 | v1 最大容許度 | 基礎傾向 | 重要度 |
|---|---:|---:|---:|---:|
| 合相 | 0° | 1.5° | 依兩顆行星性質 | 1.00 |
| 六合 | 60° | 1.0° | +.45 | .60 |
| 刑相 | 90° | 1.5° | -.75 | .90 |
| 拱相 | 120° | 1.2° | +.65 | .75 |
| 對分 | 180° | 1.5° | -.70 | .95 |

每一對天體、每一種相位，從當日 97 個實際樣本找離精確角度最近的時刻；只有最小容許度落在範圍內才成立。

`相位強度 = 1 - 實際容許度 / 最大容許度`

每領域分數：

`相位傾向 × 相位重要度 × 相位強度 × 兩行星平均領域關聯 × 宮位相關度 × 平均尊貴倍率 × 10`

`宮位相關度 = .6 + .4 × max(兩天體當時所在宮位對該領域的權重)`

同一個全球行星相位，對不同太陽星座會因落宮不同而產生不同領域影響。

v1 容許度刻意偏窄，因引擎掃描完整一天並尋找最接近精確相位的時刻。數值屬版本化模型設計，沒有宣稱是唯一正統標準。

## 11. 逆行與停滯附近

太陽、月亮不判逆行。其餘天體以 00、06、12、18、24 時四個六小時區段的實際黃經變化判斷：

- 單區段變化 < -0.002°：逆行。
- > +0.002°：順行。
- 一天至少一半區段逆行才加入逆行因素。
- 同一天同時有順行與逆行區段：視為接近方向切換，逆行摩擦權重 ×1.35。

逆行敏感度：水星 1.00；金星／火星 .80；木星／土星 .45；天王／海王／冥王 .12。

每領域：

`-3 × 敏感度 × 行星領域關聯 × (.5 + .5 × 宮位相關度) × 停滯倍率`

v1 將逆行視為輕度反覆、內收、延遲、重審摩擦，不把所有逆行直接判成大凶。

## 13. 換座與月相

- 換座完整記錄於 `AstronomyDayData`，並透過時間占比自然影響落宮／星座級相位。
- v1 不額外給換座任意吉凶分，避免重複加權。
- 新月／滿月由太陽－月亮合相／對分捕捉，不再重複計分。

## 14. 分數轉吉凶

五領域各自映射：

- `>= 10.0`：大吉
- `>= 5.5`：吉
- `>= 1.8`：小吉
- `(-1.8, 1.8)`：平
- `> -5.5`：小凶
- `> -10.0`：凶
- `<= -10.0`：大凶

綜合分數 = 五領域分數算術平均，再套同一級距。沒有先決定綜合再強迫細項跟方向的機制。

## 15. 詳情文字與改命差異

詳情禁止使用與計算無關的文案池。

每領域顯示實際分數與吉凶，從該領域 factors 找最大正貢獻與最大負貢獻組成說明。綜合顯示五項平均、最強／最弱領域與全域主要正負因素。

私人改命另以原 audit 與新 audit 比較：

- `score_after - score_before` 得到各領域與綜合差。
- 以 factor ID 找出原本存在但新天空消失的因素，以及新出現的因素。
- 綜合差 > +0.25 為改善；< -0.25 為惡化；其餘為近似不變。
- 「很遺憾」等語氣只能反映這個差異，不得修改結果。

## 16. Audit 與正式後端保存

天文 snapshot 至少保存 97 個樣本或等價資料、各天體日內星座時間占比、逆行比例、換座、主要相位最近時間與容許度。

每個星座命運保存 engine version、全部 AstrologyFactor、每因素五領域貢獻、五領域分數／吉凶、綜合分數／吉凶與最終說明。

Supabase 以 `(sky_date, ephemeris_version)` 將完整天空正規化保存一次；12 星座公共結果與私人改命只引用該 snapshot，避免重複大量天文 JSON。

公共同一天 12 筆一旦由中央端交易寫入即鎖定。即使日後升 v2，歷史仍保留原版本與 audit。

## 17. v1 明確不做

- 個人完整出生盤、上升星座、出生時間／地點。
- 假造本命太陽精確度數。
- 小行星、交點、凱龍星、阿拉伯點。
- 次要相位。
- 現代外行星的爭議性尊貴表。
- 生成式 AI 臨時判讀。
- 為了讓結果看起來隨機而加入噪音。
- 獨立亂數移動行星或生成物理不一致天空。
- 為了保證改命變好而反覆重抽。

若日後加入影響結果的新規則，必須升 `engine_version` 並新增回歸／parity 測試。
