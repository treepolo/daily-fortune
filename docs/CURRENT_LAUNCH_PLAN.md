# 目前上架計畫

> 狀態：暫定／可隨時調整
>
> 這份文件只記錄 2026-09-03 當下的工作順序，避免開發過程中偏離目前目標。它不是永久產品原則，也不限制未來產品方向；需求改變時可以直接修改或廢棄。

## 目前順序

1. ✅ 實機測試基礎抽籤功能。
   - 使用者已完成測試，目前未發現抽籤、重抽、當日保存等功能 bug。

2. ✅ v0.5 第一版廟宇視覺驗收。
   - 結論：方向正確，但 reveal 前張力不足，各吉凶視覺差距也太小。

3. 🚧 v0.6 核心互動重做。
   - 待抽畫面保留籤筒與可抓取的中央籤。
   - 使用者必須按住籤往上拉，超過門檻後才正式建立這次抽籤結果。
   - 「逆天改命!!」只回到待抽狀態，不直接產生新結果；使用者再次抽出籤後才 reroll。
   - 籤抽出後先進入更強的 suspense／結果落定動畫。
   - 接著出現原本折疊／遮蔽的籤紙；使用者按住籤紙下緣往下拖，固定版面的內容才逐步露出。
   - 籤紙版面固定為：財運 → 戀愛 → 工作／學業 → 人際 → 健康 → 總體運勢。這不是逐項程式跳出，而是同一張紙隨展開自然露出。
   - 抽籤提交、籤紙可揭、完整揭曉等重要節點加入震動回饋。
   - 每個細項依自己的 1～7 級結果套用自身視覺效果。
   - 大凶與大吉是特別極端狀態：大凶特別晦暗、低彩、壓抑；大吉特別高亮、金光與閃耀，與其他五級明顯拉開。
   - 仍維持台灣廟宇／求籤視覺方向；背景照片延後到使用者自行拍攝或找到授權乾淨素材後再加入。

4. 🚧 同版加入未來機率實驗能力，但 baseline 不啟用。
   - Remote Config 可依第幾次 reroll 指定不同完整 1～7 機率分布。
   - Remote Config 可另外啟用 pity／保底條件。
   - 預設仍為原本固定均勻分布，次數加成 OFF、保底 OFF。
   - 研究事件保留 reroll index、實際 distribution、probability policy、pity counter 與 guarantee triggered，避免後續分析把機制效果誤認成使用者行為。

5. 實機驗收 v0.6。
   - 確認往上抽籤的手勢好抓、門檻合理、不容易誤觸。
   - 確認 suspense 足夠讓人期待但不拖沓。
   - 確認籤紙往下拉的手感自然，且結果確實按固定版面逐步露出。
   - 確認震動回饋時機與強度不惱人。
   - 確認七級視覺差異足夠，其中大吉／大凶尤其醒目。
   - 確認效能、旋轉／背景切換與重開 App 行為無回歸。

6. 部署研究後端。
   - Remote Config／A/B/n 多臂實驗。
   - 匿名事件接收與資料保存。
   - 設定 Android build 所需的遠端設定與事件上傳 endpoint。

7. 做一次完整整合驗證。
   - App 能取得遠端設定。
   - 不同 installation 能穩定取得對應 experiment variant。
   - 抽籤確實使用該 treatment。
   - 動態機率 baseline 關閉時與既有均勻模型一致。
   - 研究事件可以可靠上傳並保留 config／assignment／dynamic probability 脈絡。
   - 後端不可用時，App 仍可依 cached／embedded config 正常使用。

8. 決定是否在第一版上架前加入廣告能力。
   - 若加入，先把廣告 SDK／rewarded ad 流程與 Remote Config 開關放進 App。
   - 可先以遠端設定關閉廣告，上架後再開啟；不要求第一天就實際播廣告。
   - 目前既定產品構想仍是：一般「逆天改命!!」可要求完整廣告；若當前總體結果為大吉則免廣告直接重抽。

9. 最終整合測試後準備並上架 Google Play。

## 目前刻意不做

除非 v0.6 實機驗收或上架要求顯示有必要，現在先不擴張到：

- 大量額外動畫／特效 variant
- 完整 3D 廟宇場景或真實籤筒物理模擬
- 重型粒子系統
- 完整 server-driven UI
- 為所有 padding、字級、圓角等細節建立 Remote Config
- 使用者端統計 Dashboard
- 新的產品玩法

上述項目可以在上架後依實際需求與實驗計畫逐步新增，屆時再重新調整本文件。
