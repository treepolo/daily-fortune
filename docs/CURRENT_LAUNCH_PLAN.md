# 目前上架計畫

> 狀態：暫定／可隨時調整
>
> 這份文件只記錄 2026-09-03 當下的工作順序，避免開發過程中偏離目前目標。它不是永久產品原則，也不限制未來產品方向；需求改變時可以直接修改或廢棄。

## 目前順序

1. ✅ 實機測試既有 APK。
   - 使用者已完成測試，目前未發現功能 bug。
   - 初抽、重抽、結果顯示與當日結果保存均可正常使用。

2. 🚧 完成第一版正式視覺與 reveal 體驗。
   - 這不再視為單純 UI 微調，而是第一版核心產品體驗。
   - 整體採台灣廟宇／求籤語彙：紅、金、木／竹、籤筒、籤與偏傳統字體氣質。
   - 按下抽籤後不可立即顯示結果；要有完整儀式流程與刻意保留的 suspense。
   - baseline 流程：籤筒震動 → 一支籤升起 → 短暫停頓／等待 → 結果揭曉。
   - 結果揭曉效果依 1～7 級連續增強：越凶越黯淡、低彩、壓抑；越吉越明亮、金光、華麗；大吉可有多彩光暈。
   - 重開 App 顯示既有當日結果時，不重播完整抽籤儀式。
   - 第一版先用程式化廟宇框架／紋理，不依賴外部照片；之後可替換成使用者自行拍攝或授權乾淨的廟宇照片。
   - 現階段不為「帥」而擴張成大量 3D、重型粒子、十幾套動畫或完整 server-driven UI。

3. 實機驗收新版視覺與 reveal。
   - 確認動畫節奏、等待感、結果衝擊感與不同吉凶的視覺差異。
   - 確認低階／高階 Android 裝置皆不卡頓、不閃退。
   - 若視覺主觀上仍不夠好，再針對 baseline 調整，不擴張產品範圍。

4. 部署研究後端。
   - Remote Config／A/B/n 多臂實驗。
   - 匿名事件接收與資料保存。
   - 設定 Android build 所需的遠端設定與事件上傳 endpoint。

5. 做一次完整整合驗證。
   - App 能取得遠端設定。
   - 不同 installation 能穩定取得對應 experiment variant。
   - 抽籤確實使用該 treatment。
   - 研究事件可以可靠上傳並保留 config／assignment 脈絡。
   - 後端不可用時，App 仍可依 cached／embedded config 正常使用。

6. 決定是否在第一版上架前加入廣告能力。
   - 若加入，先把廣告 SDK／rewarded ad 流程與 Remote Config 開關放進 App。
   - 可先以遠端設定關閉廣告，上架後再開啟；不要求第一天就實際播廣告。
   - 目前既定產品構想仍是：一般「逆天改命!!」可要求完整廣告；若當前總體結果為大吉則免廣告直接重抽。

7. 最終整合測試後準備並上架 Google Play。

## 目前刻意不做

除非新版實機測試或上架要求顯示有必要，現在先不擴張到：

- 大量額外動畫／特效 variant
- 完整 3D 廟宇場景
- 完整 server-driven UI
- 為所有 padding、字級、圓角等細節建立 Remote Config
- 使用者端統計 Dashboard
- 新的產品玩法

上述項目可以在上架後依實際需求與實驗計畫逐步新增，屆時再重新調整本文件。
